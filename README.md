# ראש שקט

**אומרים מה צריך. היום מסתדר.**

עוזר תכנון יום בעברית. מדברים בחופשיות, והאפליקציה הופכת את הדיבור לאירועים, משימות ותזכורות. כל פריט מוצג לאישור לפני שהוא נשמר. כשהיום משתבש, היא מציעה סדר חדש.

הגרסה הזו מממשת את "שלב ראשון" מתוך מסמך האפיון (קליטה, אישור, שמירה, מסך יום ותזכורות), וגם חלקים משלב שני: חזרתיות, התנגשויות, תכנון יומי באישור, "היום השתבש" והיסטוריה עם ביטול.

## הרצה

```bash
npm install
cp .env.example .env.local   # אופציונלי: ANTHROPIC_API_KEY=...
npm run dev                  # http://localhost:3000
npm test                     # בדיקות הקבלה
npm run build
```

**תמלול:** כדי שההקלטה תעבוד היטב באייפון, מגדירים `OPENAI_API_KEY` (מומלץ) או `ELEVENLABS_API_KEY`. ההקלטה נשלחת לשירות לתמלול בלבד ולא נשמרת.

בלי `ANTHROPIC_API_KEY` האפליקציה עובדת במלואה עם מנתח עברית מבוסס כללים. עם מפתח, הפענוח עובר דרך Claude (`claude-opus-5-5`, structured outputs). אם Claude לא זמין, המערכת חוזרת אוטומטית למנתח המקומי ומציגה על כך הודעה.

## ארכיטקטורה

| שכבה | קבצים | תפקיד |
|---|---|---|
| תמלול | `src/lib/client/recorder-controller.ts`, `src/app/api/transcribe`, `src/lib/client/speech-controller.ts` | כשמוגדר `OPENAI_API_KEY` או `ELEVENLABS_API_KEY`: הקלטה בדפדפן ותמלול בשרת, וזה עובד אמין גם באייפון. בלי מפתח: Web Speech API של הדפדפן. המיקרופון נפתח רק בהקשה, ותמיד יש חלופה בטקסט |
| חילוץ שפה | `src/lib/extraction/claude.ts`, `rules-parser.ts` | **מציע** טיוטות בלבד, ואף פעם לא כותב |
| שכבת כללים | `src/lib/extraction/validate.ts` | בדיקת שדות, עמימות, מועד שעבר, סמיכות לחצות והתנגשויות. זו הדרך היחידה מטיוטה לפריט |
| מודל ומאגר | `src/lib/domain/*` | פעולות אטומיות עם `opId`, כך שניסיון חוזר לא יוצר כפילות. כל פעולה נרשמת בהיסטוריה וניתנת לביטול |
| מנוע תכנון | `planner.ts`, `disruption.ts` | שיבוץ רק בחלונות פנויים, תוך כיבוד מועדים ותלויות. כשאין מספיק זמן מוצג עומס, לא תוכנית בלתי אפשרית |
| התראות | `reminders.ts`, `NotificationRunner.tsx`, `public/sw.js` | שעות שקטות, דחייה שלא מזיזה את האירוע, איחוד התראות ומניעת כפילות בין לשוניות |
| אחסון | `src/lib/client/store.tsx` | מקומי בלבד (localStorage), בלי חשבון ובלי שרת |

## עקרונות שמומשו מהאפיון

- שמירה אוטומטית כשהכול ברור (ניתנת לכיבוי בהגדרות). מיד אחרי השמירה מוצגת הודעה שאומרת מה נשמר ולאן, עם כפתור ביטול. כרטיס בדיקה מופיע רק כשיש שאלה פתוחה או חפיפה.
- "בשלוש" בלי הקשר לא הופך לשעה מומצאת: מוצגות שתי האפשרויות, ואי אפשר לשמור לפני שבוחרים.
- "ביום שישי" מוצג כתאריך מדויק. אם היום הוא יום שישי, המערכת שואלת אם הכוונה להיום או לשבוע הבא.
- "מתישהו השבוע" נשמר כמשימה גמישה, בלי שעה.
- "במשרד" נשמר כפי שנאמר, ולא מומר לכתובת. שמות לא מקושרים לאנשי קשר.
- אירוע קבוע לא זז אוטומטית. הפקת תוכנית ואישורה הם שני שלבים נפרדים.
- עריכה או מחיקה של אירוע חוזר מחייבות לבחור: מופע זה, מופע זה והבאים, או כל הסדרה.
- שינוי אזור זמן לא משנה בשקט מועד מוחלט: כל אירוע שומר את אזור הזמן שבו נקבע.
- ההקלטה לא נשמרת, ותוכן אישי לא נכתב ללוגים.

## סנכרון בין מכשירים

מוסיפים מסד נתונים **Postgres** לפרויקט ב־Railway, ו־`DATABASE_URL` מוגדר אוטומטית. הטבלאות נוצרות לבד בשימוש הראשון.

- **הפעלה:** במכשיר הראשון בוחרים הגדרות ← סנכרון ← "הפעלת סנכרון", ומקבלים קוד שחזור שמוצג פעם אחת בלבד.
- **חיבור מכשיר נוסף:** במכשיר המחובר בוחרים "חיבור מכשיר נוסף" ומקבלים קוד של 8 תווים, שתקף ל־10 דקות ולשימוש אחד. במכשיר החדש מזינים אותו ב־`/link`, או פותחים את הקישור שהמכשיר המחובר מציג.
- **בלי מייל ובלי סיסמה.** בשרת נשמרים רק hash של האסימונים ושל הקודים.
- **עבודה בלי רשת:** כל מכשיר עובד מקומית גם בלי רשת. כל שינוי נשלח ומתקבל אוטומטית: בפתיחה, אחרי כל שינוי, בחזרה לאפליקציה וכל 30 שניות.
- **התנגשות:** כששני מכשירים שינו אותו פריט, השינוי המאוחר יותר נשמר. מחיקות עוברות לכל המכשירים.
- **בדיקות מסד הנתונים** רצות מול Postgres אמיתי: `TEST_DATABASE_URL=postgres://... npm test`.

## מה עוד לא כאן (בכוונה)

- **חיבור ליומן חיצוני**: ממתין לבדיקת היתכנות, כפי שהאפיון ממליץ.
- **התראות כשהאפליקציה סגורה**: דורש שרת Web Push. כרגע ההתראות מוצגות כשהאפליקציה פתוחה או פעילה ברקע, והממשק אומר זאת במפורש.
- **רעיונות ההרחבה** (משפחה, מיקום, צילום ועוד): שלב המשך.
